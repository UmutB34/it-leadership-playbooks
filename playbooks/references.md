# References and frameworks used

These are the public standards and frameworks the playbooks line up with. I use them as shared vocabulary when talking to auditors, leadership and providers.

| Topic | Framework or standard |
|---|---|
| IT service management | ITIL 4 (service value system, practices for incident, request, change, problem) |
| Information security management | ISO/IEC 27001 and 27002 |
| Cybersecurity programme | NIST Cybersecurity Framework; CIS Critical Security Controls |
| Governance of IT | COBIT |
| Business continuity | ISO 22301 |
| Quality management | ISO 9001 |
| Project management | PMBOK-style practice and agile delivery |
| Reference addresses in examples | RFC 5737 documentation ranges |
| E-mail authentication | SPF, DKIM and DMARC (RFCs 7208, 6376, 7489) |
| Web security headers | OWASP Secure Headers Project |
| Web application risks | OWASP Top 10 |
| Data protection | National data protection law and GDPR where applicable |
| Internet access logging | Local legal requirements for retention and time-stamping |

## How to use them

- Pick the framework your auditor or customer already uses, and map your controls to it once.
- Keep one evidence set that serves several frameworks.
- With non-specialists, describe a control in plain language rather than by clause number.

## Note

These are practitioner notes, not legal or certification advice.
